# Производительность Lumen 0.3.11

Сравнение с 0.3.10 на этом компьютере, Windows x64 и установленном WebView2. Это предварительные инженерные замеры, а не универсальный рейтинг браузеров.

## Изменения

- Rust хранит последнее применённое состояние видимости и размеров каждой страницы. При переключении больше не отправляются одинаковые команды всем фоновым WebView. Кэш сбрасывается при пересоздании страницы.
- Одинаковое состояние не отправляется панели повторно. Повторная сериализация сессии пропускается, когда состояние не изменилось; существующая проверка содержимого перед записью на диск сохранена.
- Скрытые DevTools не получают сообщения состояния. При их загрузке/открытии состояние отправляется заново.
- Интерфейс не перерисовывает неизменившиеся настройки и параметры оформления при каждом изменении заголовка или активной вкладки.
- Косметический блокировщик собирает изменённые участки DOM, объединяет вложенные участки и проверяет их вместо всей страницы. При большом количестве изменений, первой загрузке, смене правил или включении скрытия меток выполняется полный проход. Процедурные правила с отношениями между узлами по-прежнему проверяют документ целиком.
- Политика усыпления, число создаваемых вкладок и настройки движка не изменены.

## Условия измерения

Отдельные тестовые профили, пустые новые вкладки, без расширений, блокировщик отключён для замеров оболочки. Измерены 1, 5 и 20 вкладок. Скрипт собирает дочерние процессы именно тестового Lumen, включая WebView2. Рабочие наборы процессов суммируются: общая память может учитываться несколько раз, это не уникальная физическая память/PSS.

Задержки создания/переключения — время до получения состояния панелью через IPC. Время первого нарисованного кадра отдельно не измерялось. Для переключения взята медиана 10 действий в каждом прогоне. CPU измерялся за двухсекундный простой и выражен в процентах одного ядра.

## Прогретые профили

Один полный прогон каждой версии; небольшие различия могут быть шумом.

| Показатель | 0.3.10 | 0.3.11 |
| --- | ---: | ---: |
| Запуск до готовности панели | 721.7 мс | 628.4 мс |
| Создание новой вкладки, среднее 19 действий | 49.97 мс | 48.15 мс |
| Переключение при 5 вкладках, медиана | 3.6 мс | 3.4 мс |
| Переключение при 20 вкладках, медиана | 3.9 мс | 3.8 мс |
| Сумма рабочих наборов, 1 вкладка | 495.2 МиБ | 490.1 МиБ |
| Сумма рабочих наборов, 5 вкладок | 529.5 МиБ | 524.0 МиБ |
| Сумма рабочих наборов, 20 вкладок | 643.8 МиБ | 636.1 МиБ |

В прогретом прогоне число процессов совпало: 9 / 13 / 28. Измеренный CPU простоя округлился до 0.00% у обеих версий; это не означает отсутствие работы процессора. Доказанного существенного уменьшения RAM нет.

## Новые профили и разброс

Три запуска на отдельных новых профилях:

- 0.3.10: 725.9, 724.9, 632.4 мс; медиана 724.9 мс.
- 0.3.11: 1968.6, 632.2, 632.9 мс; медиана 632.9 мс.

Первый результат 0.3.11 заметно выбивается; он сохранён в отчёте. Причина выброса не установлена. Гарантированное ускорение холодного старта не заявляется.

В первых полных прогонах создание вкладки составило 73.68 → 64.85 мс, а память при 20 вкладках — 817.7 → 715.4 МиБ. Разброс относительно прогретых прогонов показывает, почему эти значения нельзя выдавать за устойчивый выигрыш.

## Косметический блокировщик

Обе версии runtime запущены последовательно в одном WebView2 на одинаковой тестовой странице: 6000 обычных карточек по 3 текстовых элемента. После первого полного прохода выполнено пять изменений текста одной карточки с паузами для обработки.

| Объём обхода после пяти изменений | До | После |
| --- | ---: | ---: |
| Вызовы TreeWalker.nextNode, включая завершение прохода | 90 005 | 20 |

После изменения проверяется небольшая карточка, а не весь документ. Эти числа описывают объём текстового обхода, не скорость браузера в целом и не полное время работы фильтра. Проверки рекламы Яндекса, закрытых Shadow DOM, поздней смены рекламной метки и повторного включения скрытия выполняются отдельно.

## Воспроизведение

Из каталога исходников, в PowerShell:

```powershell
./tools/benchmark-lumen.ps1 -Executable 'C:\path\lumen.exe' -DataDirectory 'C:\path\isolated-profile' -OutputFile 'C:\path\result.json'
```

Для одного запуска с одной вкладкой добавьте `-TabCounts 1`. Скрипт задаёт настройки и создаёт страницы в указанном профиле, поэтому используйте отдельный тестовый каталог.

Для сравнения косметических скриптов запустите отдельный Lumen с тестовым профилем, содержащим новую вкладку, и передайте сохранённый runtime предыдущей версии:

```powershell
./tools/benchmark-cosmetic.ps1 -DataDirectory 'C:\path\isolated-profile' -BaselineRuntime 'C:\path\old-runtime.js' -OutputFile 'C:\path\cosmetic.json'
```

Сырые результаты этого сравнения находятся в папке `benchmarks/0.3.11`.
