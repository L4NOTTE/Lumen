# Обновления Lumen

## Поведение Windows 0.5.0

При запуске основного обычного процесса Lumen асинхронно проверяет стабильный канал GitHub Releases. Если подписанный и действующий манифест содержит версию выше установленной и корректный артефакт для Windows, внутри браузера появляется уведомление примерно на семь секунд. Оно показывается один раз за запуск после готовности интерфейса. При последующей готовности установщика повторное всплывающее сообщение в том же запуске не появляется. Статус в настройках обновляется.

Портативная версия проверяет тот же канал и предлагает скачать новый ZIP. Установщик для неё автоматически не загружается и не применяется. Равная или более старая версия, ошибка сети, неверная подпись и истёкший манифест не вызывают сообщение о новом выпуске.

Проверка повторяется через шесть часов и по кнопке «Проверить обновления». Отдельные окна одного обычного процесса используют общую проверку. Инкогнито и вторичные процессы отдельную проверку не запускают.

Для уведомления в GitHub нужен стабильный релиз с числовым тегом `v<версия>`, например `v0.5.1` и подписанным `lumen-update.json` в канале Latest. Черновик и предварительный релиз не попадают в этот канал. Локально собранная 0.5.0 сообщит только о более новой версии.

## Установка обновления

Начиная с 0.4.24 браузер проверяет `lumen-update.json` в последнем релизе `L4NOTTE/LUMEN-IS-Web-browser`. Для перехода с 0.4.23 и более ранних версий закройте Lumen и один раз запустите установщик 0.4.24 вручную. Подходящая версия загружается в фоне. В Windows нажмите «Перезапустить и обновить» в настройках, когда пакет будет проверен. Перед перезапуском завершите загрузки и верните вкладки из отдельных окон. Lumen сохраняет адреса HTTP/HTTPS и восстанавливает активную вкладку. Обновление также может примениться при обычном закрытии браузера после завершения загрузок. Для Windows используется установщик Inno Setup. Для Linux заменяется пользовательский бинарник `~/.local/bin/lumen`. Для системного `.deb` используется менеджер пакетов. На Linux для проверки обновлений нужен `/usr/bin/curl`.

Манифест проверяется встроенным ключом Ed25519. Он содержит версию, срок действия, размер и SHA-256 каждого артефакта. Браузер проверяет файл повторно перед применением. Подпись манифеста авторизует обновление внутри Lumen. Authenticode для доверия Windows настраивается отдельно по SIGNING.md.

## Предварительные сборки

0.5.0 подготовлена к выпуску для Windows. Итоговые EXE, два ZIP и подписанный манифест находятся в `publish/classic`. Для последующих предварительных выпусков используйте отдельный тег с отметкой Pre-release.

Для предварительных релизов оставляйте манифест автообновления в стабильном канале. Обновлятор принимает только числовую версию из трёх частей, например `0.4.24`, и ищет манифест по пути `releases/latest/download/lumen-update.json`.

## Стабильные релизы

Обновите внутреннюю версию, соберите установщик и проверьте его. Сформируйте манифест по финальным файлам. Если файл меняется после подписи манифеста, подпишите манифест заново.

Публикуйте файлы в GitHub Releases в репозитории `L4NOTTE/LUMEN-IS-Web-browser` под тегом `v<версия>`. Отметьте стабильный релиз как Latest. Прикрепите установщик и манифест отдельными файлами.

Каждый Windows x64 релиз собирайте в отдельную папку `publish/classic` с двумя ZIP и двумя EXE. Сохраняйте имена и регистр:

- `Lumen.x64.zip` содержит `Lumen.x64/LumenSetup.exe`.
- `Portable.x64.zip` содержит папку `Portable.x64/Lumen-Portable/` с `Lumen.cmd`, `lumen.exe`, `xray.exe` и сопровождающими документами.
- `LumenSetup.exe` — отдельный установщик. Это имя использует автообновление.
- `lumen.exe` — отдельный EXE браузера. Для VPN рядом нужен `xray.exe` из той же сборки.

Рядом положите `SHA256SUMS.txt` с контрольными суммами и подписанный `lumen-update.json`. Проверьте, что установщик внутри `Lumen.x64.zip` побайтово совпадает с отдельным `LumenSetup.exe`, на который ссылается манифест.

Если есть проверенная сборка Linux x64, добавьте `lumen-linux-x64` в релиз и в подписанный манифест.

Пример подписи Windows-выпуска в PowerShell на машине владельца ключа:

```powershell
./tools/sign-update-local.ps1 -Version 0.5.0 -WindowsInstaller ./LumenSetup.exe -Output ./lumen-update.json -ProtectedKey 'C:\path\to\private.dpapi'
```

Для выпуска с Linux добавьте `-LinuxBinary ./lumen-linux-x64`. Версия должна соответствовать собранному исходному коду и тегу. Срок действия манифеста составляет 30 дней. Приватный ключ хранится вне исходников под DPAPI текущего пользователя Windows. Сохраняйте доступ к ключу, чтобы установленный браузер мог принимать будущие релизы.

Для CI скрипт `tools/sign-update.cjs` принимает ключ PKCS#8 Ed25519 в Base64 через секрет `LUMEN_UPDATE_PRIVATE_KEY_BASE64` или стандартный ввод. Запускайте подпись только после проверки финальных файлов. Lumen проверяет канал при запуске и каждые шесть часов до получения подходящего обновления. На Windows итог попытки установки записывается в %LOCALAPPDATA%/Lumen/update-status.txt. Нативный цикл через опубликованный канал проверяется после первого публичного релиза с подписанным манифестом.
