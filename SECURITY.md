# Безопасность Lumen 0.4.11

## Изменения в 0.4.13

В запросе Shazam системный звук разрешается кнопкой в отдельной защищённой области того же окна. Сообщения расширения могут запросить или остановить захват. Подтверждение поступает только из интерфейса Lumen.

В истории, файле восстановления и журнале загрузок очищаются известные параметры авторизации, учётные данные и фрагменты URL. При открытии профиля обрабатываются и прежние записи. Процесс очистки Windows запускается при создании приватного профиля и ждёт завершения процесса браузера.


Файлы профиля и журнал загрузок читаются с ограничением размера. Проверяется тип файла, чтение конечных символических ссылок и reparse points запрещено. Перезапись сеанса, закладок, фона, карты расширений, истории и журнала загрузок выполняется атомарно. Запись строки в историю Windows также проверяет число жёстких ссылок по открытому дескриптору. При закрытии обычного окна удаляются его незавершённые запросы переноса вкладок.

Стартовая страница использует CSP с SHA-256 штатного скрипта. Быстрые ссылки передаются как JSON, внешние ресурсы заблокированы, referrer отключён. Нативный тест WebView2 подтвердил отрисовку ссылки, отправку поиска и блокировку внедрённого inline-скрипта. Для Linux выполнена проверка синтаксиса исходников, нативный тест остаётся в очереди.

# История 0.4.10

Внешняя страница могла отправить навигацию на `https://lumen.invalid/s` и заставить старый Windows-браузер обработать её как поиск со стартовой страницы. В 0.4.10 внутренние команды требуют случайный токен окна, точный адрес обработчика и состояние стартовой страницы. Отдельно проверены поддельный, отсутствующий и повторяющийся токен. Атака воспроизведена на 0.4.9 и заблокирована в нативной проверке 0.4.10. Стартовая страница рисует буквы вместо сетевых запросов иконок закреплённых сайтов.

Перенос вкладок в инкогнито запрещён. Обычный перенос использует каталог профиля, ограничение размеров файлов и удаление запроса при тайм-ауте. Shazam требует подтверждения системного захвата в нативном диалоге и останавливает запись через 20 секунд. Помощник обновления держит файл установщика открытым с запретом записи и удаления во время повторной проверки и запуска. Подписанный тестовый исполняемый файл запустился с этим ограничением.

28 Rust-тестов и JS-контракт Shazam прошли. В локальной базе RustSec найдено ноль записей категории vulnerability, остаются три предупреждения unmaintained и одно unsound. Нативный Linux и реальное распознавание звука в этом выпуске не проверены.

DevTools открывается через локальный API движка из обычной вкладки. Старые параметры запуска и переменные отладки не включают сервер CDP. Расширения Windows восстановлены в обычных окнах. Расширения используют выданные им разрешения. Нативный мост Shazam принимает сообщения только от его идентификатора и использует системный WASAPI loopback. Запросы разрешений сайтов отклоняются, автозаполнение и сохранение паролей WebView2 отключены. Windows использует строгую защиту от трекинга, Linux использует WebKit ITP. Для Windows также задано ограничение WebRTC на непроксируемый UDP.

Автообновление проверяет подпись Ed25519, версию, срок действия, размер и SHA-256. Помощник Windows повторяет проверку после выхода браузера. Подпись выпуска и инструкция публикации описаны в [UPDATES.md](UPDATES.md).

Границы защиты включают обычное раскрытие IP при соединении с сайтом, данные, которые пользователь отправляет сайту, локальные данные профиля и возможные уязвимости движка или ОС. Нативная проверка Ubuntu/Mint и установка из опубликованного канала остаются отдельными проверками перед заявлением готовности на этих платформах.

# Исторические изменения 0.4.5

Windows открывает штатный инспектор через OpenDevToolsWindow. Код для создания TCP-порта и встраивания удалённого фронтенда удалён в 0.4.12. Для Linux используется инспектор WebKitGTK, переменные удалённой отладки очищаются при запуске.

Автоматическое распознавание Shazam по-прежнему захватывает системный loopback, а не звук одного процесса.

Окна расширений не допускают навигации на другой origin или открытия дочерних окон. Содержимое сторонних расширений не считается доверенным кодом Lumen. Полная собственная модель разрешений расширений пока не реализована.

Linux: каталог настроек и профиль WebKit — 0700, конечный symlink вместо каталога отклоняется; сохранение выполняется через tempfile и атомарную замену. Это не защита от вредоносного процесса с правами того же пользователя. glib 0.18.5 включён в vendor с минимальным исправлением RUSTSEC-2024-0429 (см. vendor/GLIB-PATCH.md); это backport, не обновление версии. Оптимизированный regression test добавлен в Linux CI, но здесь не запускался.

Остаются: проверка Linux в настоящей Ubuntu/Mint, X11/Wayland, разрешения сайтов/расширений, длительные стресс-тесты, обновление устаревшего GTK3-стека и предупреждения транзитивных зависимостей. Отсутствие всех уязвимостей не заявляется. Далее сохранён исторический аудит 0.4.2; его пункт о постоянно открытом CDP заменён изменениями выше.

# Исторический аудит безопасности Lumen 0.4.2

Дата: 11 ноября 2026 года. Проверена локальная кодовая база, происходящая от Lumen 0.4.1; исправления выпущены как 0.4.2. **Это инженерный аудит с воспроизводимыми тестами, а не сертификация и не гарантия отсутствия всех уязвимостей.** У текущей архитектуры остаются риски, перечисленные ниже. Для публичного браузера их необходимо отдельно устранить или явно ограничить поддерживаемую модель угроз.

## Область и условия

Проверялись границы между сайтами, интерфейсом, DevTools и Rust; установка расширений; CRX/ZIP; загрузки и работа с путями; настройки и инкогнито; системные процессы и сетевые загрузки; зависимости и CI. Тесты Windows запускались с отдельными профилями, локальными HTTP-серверами и искусственными данными. Пользовательские cookies, пароли, настоящие API-ключи и системный звук в тесты не включались. GitHub-репозиторий и релизы не менялись.

Среда: Windows x64, rustc 1.99.1, WebView2 Runtime 157.0.4341.46. Linux-ветка проверена по Rust-типам; нативная сборка, линковка и запуск Linux не выполнялись.

Различаются обычная недоверенная веб-страница, доверенный интерфейс браузера, установленное расширение и локальный процесс. Локальный процесс с доступом к отладочному порту — отдельный существенный риск, который исправления IPC полностью не устраняют.

## Реально выполненные проверки

- **20 Rust-тестов успешно**, включая реальные CRX-файлы Shazam/VK Next и их изменения. Отдельный нативный тест анимации, максимизации и двух циклов fullscreen тоже выполнен успешно: суммарно **21 тест**, без пропущенных тестов в этих двух запусках.
- **10 000 детерминированных повреждённых входов CRX/protobuf** обработаны без panic. Это ограниченный smoke-fuzz, не coverage-guided fuzzing и не доказательство безопасности парсера.
- `verify-security.cjs`: 5 воспроизведений/контрольных наблюдений на 0.4.1; **10 проверок исправленного release**. Есть сравнение до/после, запрет внедрённого script, чужой UI-навигации, посторонних команд DevTools, изменение фона, приватные расширения и очистка приватного профиля.
- `verify-browser-regressions.ps1`: перестановка вкладок мышью, сохранение DOM и страницы; обычные/закрытые/поздние рекламные карточки; макет Shazam 360/470 px; кнопки UI; Elements, Console, Sources, Network, Performance, Application; выбор конкретного DOM-узла; оформление консоли в двух темах — успешно.
- `verify-downloads.ps1`: нативное скачивание, промежуточные байты, дубликаты имён, две одновременные загрузки одного URL, ссылка страницы, отмена, обрыв соединения, история, инкогнито, поиск и 360/800 px — успешно на release.
- `verify-zoom-persistence.ps1`: реальный масштаб, разные origin, навигация, новая вкладка, перезапуск, инкогнито и сброс — успешно.
- Node-контракт Shazam capture — успешно; настоящая запись/передача аудио в этом аудите не выполнялась.
- Clippy: ошибок категории correctness не найдено; остаются стилистические предупреждения существующего кода (7 различных видов). Это не полный SAST и не анализ корректности всех unsafe/FFI-вызовов.
- RustSec: cargo-audit 0.23.0, база из 1458 advisories, commit fd6f39814c4d3c359fdbe223d0280dec4933f78f, обновлена 11.11.2026. В разделе vulnerability — 0, но **есть 5 informational предупреждений**; они не скрыты и не объявляются исправленными.
- Ограниченный поиск характерных приватных ключей/GitHub/AWS credentials в 68 текстовых файлах исходников и отчётов: совпадений нет. Это не полноценный secret scanner; значения не выводились.
- Повторный Linux all-targets typecheck успешен с временным wrapper только для системных build.rs GTK (отключает pkg-config отсутствующего Linux SDK). Настоящие биндинги и код приложения не заменялись. Это **не** проверка ABI, линковки, рабочего стола или загрузок в Linux.

Машиночитаемые результаты: [security/2026-11-11](security/2026-11-11). Команды и инструменты находятся в tools/. Новые GitHub workflow здесь не запускались.

## Что остаётся открытым

1. **Высокий локальный риск: неаутентифицированный CDP endpoint.** Нынешний полный боковой DevTools работает через постоянно включённый WebView2 remote debugging на 127.0.0.1. Локальный клиент, который может подключиться к этому адресу, может перечислять targets, выполнять JS и управлять страницами; защищённый UI CSP не является защитой от уполномоченного CDP-клиента. Наши тесты подключаются именно так. Проверка отправителя IPC не закрывает чтение данных страниц через CDP. Самостоятельный доступ из интернет-страницы, обход проверок Origin WebSocket или соединение с другого компьютера не доказаны. Для публичной защищённой версии нужен иной транспорт/изолированный аутентифицированный мост либо отключение remote debugging по умолчанию с явным режимом отладки. Функциональность текущего бокового инспектора здесь не удалялась.
2. **Зависимости:** instant 0.1.13 (RUSTSEC-2024-0384, через tao, Windows/Linux); glib 0.18.5 (RUSTSEC-2024-0429, unsound VariantStrIter, Linux GTK3); proc-macro-error 1.0.4 (RUSTSEC-2024-0370, Linux GTK build); fxhash 0.2.1 (RUSTSEC-2025-0057) и rand 0.7.3 (RUSTSEC-2026-0097) присутствуют в общем lockfile, но не входят в проверенные Windows/Linux dependency graphs. У rand предупреждение связано с определёнными сочетаниями custom logger/thread_rng; его эксплуатация в Lumen не установлена. glib требует обновления стека или проверенного backport до признания Linux-порта готовым. Простая замена glib 0.18 на 0.20 несовместима с текущими GTK3 API. Weekly cargo-audit не скрывает предупреждения, но при нынешних informational advisories может завершаться успешно: зелёный CI не означает отсутствия этих рисков.
3. **Расширения и приватность:** подпись подтверждает издателя/ID и целостность, а не безопасность. Собственной модели показа и согласования всех разрешений Chrome-расширений пока нет. Локальная распакованная папка — явно доверенная developer-установка без подписи. Shazam получает системный WASAPI loopback, **не только звук процесса браузера**, на время распознавания; это ограничение сохранено.
4. **Движок и ОС:** WebView2/Chromium и системный WebKitGTK не проходили аудит исходников/эксплойт-тестирование в рамках этой работы. Sandbox, TLS и SmartScreen не отключались в коде браузера; обновления движка и ОС обязательны. Отсутствие TLS override в коде не является полноценным тестом всех сертификатов и разрешений устройств.
5. Не выполнены независимый пентест, длительный coverage-guided fuzzing, ASan/Miri для всех путей, многочасовые стресс-тесты, ручная проверка каждого сайта/DRM, реальный захват звука, полная проверка переноса между несколькими видимыми окнами/мониторами и нативная Linux-сессия. Подписывание EXE/установщика и автоматическое защищённое обновление приложения не реализованы.

## Порядок дальнейшей работы

Сначала закрыть локальную границу CDP и определить модель разрешений/секретов; затем подготовить GTK/WebKitGTK-зависимости и воспроизводимую нативную Ubuntu/Mint сборку, выполнить там те же тесты и отдельные проверки X11/Wayland, прав профиля, media/permissions и Inspector. Полный перенос Windows-функций на Linux в этот аудит не включён.
